# Design

## Context

动机见 proposal.md。项目采用 Electron + React 19 + TypeScript；浏览器模式复用同一 renderer，通过 webBridge 调用 HTTP。`main/settings.ts` 将配置保存到用户数据目录，并经 `SettingsPublic`/`SettingsPatch` 暴露；当前没有 locale 字段或翻译模块。

文字不只存在于 JSX：App 的 NAV/TITLES、Settings 的 SECTIONS/AUDIO、ui 的 StatusPill、KindArt、Thumb、shared 的 nodes/templates/animSystems/comfyServers 等包含静态显示元数据。main 的菜单、任务栏、文件对话框、Web 认证 HTML 和错误也包含土耳其语。`store.tsx` 将 `Üretildi` 写入资产状态，Library 用这个值着色，不能直接替换成中文。多处搜索和数字/日期格式硬编码 `tr`/`tr-TR`。完整映射见 ui-audit.md。

## Goals / Non-Goals

**Goals:** 用统一消息键覆盖 renderer、main 和 shared 的显示边界；即时切换不重新挂载业务状态；可自动验证词典与残留文字；保持 Electron/HTTP 权限边界与旧项目兼容。

**Non-Goals:** 不重新设计页面，不自动翻译历史对话/用户项目，不改变服务提示词、生成内容或执行参数，不本地化安装器和外部应用；操作系统自带文件选择器内部按钮由系统语言决定。

## Decisions

### 1. 纯共享词典 + React 响应式语言上下文

新增 `src/shared/i18n/`，包含 locale 类型、解析/归一化、消息键、三个词典、插值和 Intl 工具。用英语词典定义键及参数契约，中文/土耳其语要求同等覆盖。React 使用 provider/hook 订阅 locale；main 显式传 locale，不依赖全局可变语言。富文本采用翻译片段和 React 元素组合，不使用不可信 HTML 注入。

静态数组存键或由 locale 派生，避免模块加载时翻译后永远缓存。useMemo/useCallback 纳入语言依赖；任务回调、已有 toast 和自定义弹窗保存 message key + params，在显示时翻译，防止闭包捕获旧语言。仅发生在下一次打开的系统原生对话框使用新语言。

备选：引入完整 i18n 框架可提供更丰富工具，但目前不需要额外运行时依赖；DOM 文本替换容易遗漏属性、动态参数且误伤用户内容，不能采用。

### 2. 主机保存语言，原子切换，兼容旧配置

locale 为 `en | zh-CN | tr`。在 SettingsFile/Public/Patch 增加字段，main 归一化旧配置：显式保存值优先，否则 Electron 系统语言识别 `zh-CN`、`zh-SG`、`zh-Hans*` 为简中，`tr*` 为土语，其他为英语。无效磁盘值按未设置处理；无效提交在任何设置修改前拒绝。浏览器由主机配置决定语言，不以各客户端浏览器语言覆盖主机选择。

Settings 页在类别区外提供语言选择，不受搜索结果或缺少 API key 的自动分类跳转影响。保存成功后更新 provider；失败保留旧值。启动先获得有效语言再显示业务界面，避免土耳其语闪现；初始占位不展示错误语言控件。更新 document.lang，CSS 补充中文系统字体 fallback。

沿现有事件通道增加脱敏的 locale 变更通知（不发送 secrets），桌面和 Web 客户端订阅更新；注销订阅避免泄漏。保留 settings.set 的 owner-only 规则；editor/viewer 跟随主机语言，不新增设置权限。备选的每浏览器独立语言偏好会扩大设置权限和同步规则，本次不采用。

### 3. 数据值与显示文案严格分离

内部 enum、ID、API 字段、参数值、文件路径和提示词保持原样。为已知资产状态、kind、job 状态、node/port/param、预设标签提供显示映射。自定义字符串不做词典查找或全局替换。

内置模板已有内容可能被复制到项目：按稳定模板 ID 且名称仍等于原始内置默认值时才投影翻译；用户改名保留原值。动画系统/clip 使用稳定模板和 clip key。新建实例的默认名字可以按当前语言生成，保存后作为可编辑内容，不在切换时重写。显示样例卡片和点击后发出的默认用户消息均提供对应语言，但服务端系统提示词不变。

备选：将现有项目中的土耳其语批量改成英文会损坏自定义内容、状态匹配与兼容性，不采用。

### 4. 结构化应用反馈与原始诊断共存

为跨 IPC/HTTP、任务事件和 shared QA 暴露的应用消息增加可选 `{ key, params }` 描述，保留旧 string/日志字段兼容现有调用者和文件。建立统一的 UI 错误呈现边界，区分已知应用消息与外部服务原始详情。新增字段要通过 preload 及 Web 错误封装完整传递；旧任务记录中已知固定应用消息按精确格式映射，无法识别的历史日志原样保留为诊断内容。

不得靠识别土耳其语字符判定能否翻译：许多字符串没有特有字母。要追踪 renderer 实际显示的错误/警告/QA 字段及 main/shared 生产者。认证 HTML 使用同一词典、主机语言和现有 HTML escaping/CSP。

### 5. 原生菜单与第三方组件显式处理

locale 更新时重建 tray 和 Windows jump list；main 调用 dialog 时动态构造应用标题/按钮/过滤器名。ReactFlow 的 Controls 和可访问性文案显式传入本地化配置。文件名、扩展名、程序产品名不译；系统拥有的 UI 不纳入词典。

### 6. 按可达界面验收，而非只数已替换字面量

ui-audit.md 是代码检查建立的覆盖矩阵，实施时每行记录字符串来源、验证状态和证据。自动测试检查键一致性、占位符、fallback、locale 解析、持久保存、权限和消息序列化；源码扫描识别 JSX 文本/属性、字符串选项和反馈调用，例外逐条说明。仅正则检测土耳其语不是完成标准。

运行现有 typecheck、lint、format、单测、build；新增必要集成验证：切换同时有未保存编辑和运行任务、重启、IPC/Web 同步、原生菜单和旧项目。逐页以英语/简中点击并目测，覆盖空/有数据/错误状态；对 tr 做回归。无真实服务凭证时用确定性本地 fixture，记录真实服务未验收项，不能以其为由漏译应用控件。

## Risks / Trade-offs

- [字符串分散且共享模块同时参与业务] → 显示层适配器与稳定消息键；对旧资产状态、节点执行参数和自定义名做不变性回归测试。
- [后台消息切换后仍使用旧语言] → 持久对象携带消息键，在呈现时翻译，回调不缓存已格式化消息。
- [译文字长导致列表/按钮裁切] → 双语逐页视觉检查，允许换行、弹性宽度和完整 tooltip，中文字体 fallback。
- [浏览器语言事件泄露设置] → 专用 locale payload，复用鉴权订阅，不广播整个设置对象。
- [历史外部错误与 AI 内容仍为原始语言] → 作为数据明确保留，并将所有应用解释与操作控件本地化。
- [缺少 DOM 测试环境] → 优先沿现有 Vitest 测纯函数、IPC/HTTP 契约，应用级流程用受控 fixture 与人工/自动 UI 验证，不为测试强加大型框架。

## Migration Plan

先接入基础词典和 locale 字段/同步，再逐组迁移所有 UI 与反馈，最后启用完整覆盖检查。原有配置无需用户操作；项目文件不批量迁移。完成前不将部分覆盖声明为可发布结果。回退时旧版本会忽略新增 locale/消息元数据，既有字符串与项目执行参数继续可用。
